\subsection{Cross-Paper Graph Comparison}

While text-based analysis captures semantic relationships between papers, visual content---particularly graphs, figures, and experimental results---often conveys critical information that is difficult to extract from prose alone. Performance curves, architecture diagrams, and ablation study visualizations provide direct evidence of methodological differences and empirical outcomes. A researcher comparing two papers on 3D object detection might find that both report similar mAP scores in their abstracts, but visual inspection of their performance curves reveals that one method excels on small objects while the other performs better on large objects---a distinction that would be missed by text-only analysis. Similarly, architecture diagrams can reveal structural similarities between methods that are described using different terminology, while ablation study visualizations can highlight which components contribute most to performance gains.

To enable systematic comparison of visual content across multiple papers, we introduce a \textit{Cross-Paper Graph Comparison} module that extracts, indexes, and compares figures from PDFs using multimodal embeddings and vision-language models. The module operates in three stages: (1) graph extraction and indexing from multiple PDFs, (2) multimodal similarity search to identify relevant graphs, and (3) pairwise comparison and report generation using vision-language models. This pipeline transforms the manual, time-consuming process of visually comparing experimental results across papers into an automated, scalable workflow that supports both exploratory research and systematic prior-art checking.

\textbf{Stage 1: Graph Extraction and Indexing.} The module builds on the \texttt{ImageExtractorTool}, which parses PDF content lists generated by Mineru's PDF parsing pipeline to identify and extract all figures and graphs. For each PDF in the input corpus, the system loads the structured content list JSON file that contains metadata about all document elements, including images, tables, and their associated captions. The extraction process iterates through each content block, identifying blocks with type \texttt{image}, and extracts the relative image path, caption text, and page number.

For each extracted graph, the system stores comprehensive metadata including the source PDF name, page number, caption text (with support for multiple caption variants if available), and the saved image path. The system creates a hierarchical directory structure organized by task name (e.g., \texttt{benchmark\_landscape}, \texttt{prior\_art\_check}) and PDF name, with separate subdirectories for graphs and tables. This organization supports multi-session workflows where different research questions may require different visual comparisons, and allows the system to efficiently locate and retrieve graphs when processing comparison queries.

The extraction process handles edge cases such as missing captions (falling back to generic figure labels), invalid file paths, and image format variations. Each extracted graph is assigned a unique identifier combining the PDF name and a sequential graph index (e.g., \texttt{paper1\_graph\_001}), enabling traceability back to the source document. The metadata structure also preserves the original block data from Mineru, allowing downstream analysis to access additional context such as surrounding text or section information if needed.

\textbf{Stage 2: Multimodal Similarity Search.} To find relevant graphs across papers given a user query (e.g., ``accuracy comparison curves'' or ``architecture diagrams''), the system supports two complementary similarity search modes that capture different aspects of graph relevance.

\textit{Visual Similarity:} Using CLIP-based vision-language embeddings (e.g., \texttt{openai/clip-vit-base-patch32}), the system computes dense vector representations for each graph image. The embedding model processes the raw image pixels and produces a fixed-dimensional vector that captures visual structure, chart types, graphical patterns, and layout characteristics. When a user provides a query, the system embeds either a query graph image (if provided) or the text description into the same embedding space, enabling retrieval based on visual similarity. This approach is particularly powerful for finding similar experimental setups, performance curves, or architectural diagrams that share visual characteristics even when described differently in captions. For instance, a query for ``line plots showing accuracy over epochs'' can retrieve graphs that visually match this pattern, regardless of whether their captions explicitly mention ``accuracy'' or ``epochs.''

\textit{Semantic Similarity:} Graph captions are embedded using text embedding models (e.g., OpenAI's \texttt{text-embedding-3-small}) to capture semantic relationships. This allows the system to identify graphs that address similar research questions or evaluation metrics, even if their visual appearance differs. For example, a query for ``accuracy comparison curves'' can retrieve both line plots and bar charts that compare model performance, as long as their captions indicate they show accuracy comparisons. This semantic matching is crucial when different papers use different visualization styles to present similar information, or when the same type of experimental result is visualized in different formats (e.g., confusion matrices vs. ROC curves for classification tasks).

The system computes similarity scores for both modalities independently. For visual similarity, it calculates the cosine similarity between the query embedding and each graph's visual embedding. For semantic similarity, it computes the cosine similarity between the query text embedding and each graph's caption embedding. The system then combines both signals using a weighted score (default: 60\% visual, 40\% semantic), though users can specify comparison types (\texttt{visual}, \texttt{semantic}, or \texttt{all}) to emphasize different aspects of similarity. This flexibility allows researchers to tailor the search to their specific needs: visual-only search is useful when looking for graphs with similar structures or patterns, semantic-only search is effective when the research question is about content rather than visualization style, and combined search provides a balanced approach that considers both aspects.

The similarity search process handles large corpora efficiently by computing embeddings in batches and caching results to avoid redundant computations when processing multiple queries over the same graph collection. The system returns the top-$k$ most similar graphs (default $k=5$), ranked by the combined similarity score, along with individual visual and semantic scores for transparency.

\textbf{Stage 3: Pairwise Comparison and Report Generation.} For the top-$k$ most similar graphs, the system performs detailed pairwise comparisons using a multimodal LLM that can process both images and text. Each comparison analyzes four key dimensions: (1) \textit{Similarities}, identifying common elements, shared axes, overlapping experimental conditions, and similar trends or patterns; (2) \textit{Differences}, highlighting distinct design choices, diverging results, methodological variations, and unique features; (3) \textit{Performance Assessment}, when applicable, determining which graph shows better results, more comprehensive evaluation, or more rigorous experimental design; and (4) \textit{Patterns and Trends}, extracting notable observations that emerge from visual inspection, such as convergence behavior, outlier points, or systematic biases.

The comparison leverages both the graph images and their captions, enabling the LLM to ground its analysis in both visual evidence and textual context. The system constructs a structured prompt that includes the graph images (when available), their captions, source paper information, and specific instructions for the comparison task. The multimodal LLM processes this input to generate detailed, evidence-based comparisons that go beyond simple visual matching to provide interpretable insights about the relationships between graphs.

This dual-modality approach helps identify cases where visual patterns align with or contradict textual claims, supporting more robust evidence-based analysis. For example, if two papers claim similar performance improvements but their graphs show different curve shapes or convergence behaviors, the comparison will highlight these discrepancies. Conversely, if graphs from different papers show similar visual patterns but their captions describe different experimental setups, the comparison can identify potential methodological connections that might not be apparent from text alone.

The system generates a structured comparison report that includes: (1) a summary of the query and search parameters, (2) a ranked list of similar graphs with their similarity scores and metadata, (3) pairwise comparisons between the top graphs, and (4) summaries grouped by source paper to help researchers understand which papers contain the most relevant visual evidence. The report is formatted in Markdown for human readability and includes file paths to the extracted graph images, enabling researchers to directly inspect the visual evidence.

\textbf{Integration with Research Tasks.} The graph comparison module integrates seamlessly with both \texttt{benchmark\_landscape} and \texttt{prior\_art\_check} tasks, extending their capabilities with visual evidence analysis. In benchmark landscape analysis, researchers can query for graphs showing performance comparisons across datasets or methods, enabling rapid identification of state-of-the-art results and evaluation protocols. The module helps answer questions like ``Which papers show the best performance on KITTI dataset?'' or ``How do different methods compare in terms of inference speed?'' by directly analyzing the visual evidence rather than relying solely on textual descriptions.

In prior art checking, the module helps identify papers that present similar experimental results or use comparable evaluation setups, providing visual evidence to complement text-based overlap analysis. When checking for prior art on a new method, researchers can use graph comparison to find papers with similar performance curves, architecture diagrams, or ablation study results, even if the textual descriptions differ. This visual evidence can strengthen or weaken claims about novelty: if a proposed method's performance curve closely matches an existing method's curve, this visual similarity provides strong evidence of potential overlap, while if the curves show distinct patterns, this supports claims of methodological differences.

The module outputs structured comparison reports that include similarity scores, extracted graph metadata, pairwise analysis, and summaries grouped by source paper. This enables researchers to quickly identify which papers contain the most relevant visual evidence for their research questions and understand how experimental results compare across the literature. By automating the extraction, indexing, and comparison of visual content, the module significantly reduces the time required for comprehensive literature review while improving the quality and completeness of evidence-based analysis.
